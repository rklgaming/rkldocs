Gear · Forge · Crafting · Magic · Seasonal

RKL Suite — Developer Docs

Connected FiveM resources for RPG servers: wearable gear with stats and durability, a forge for upgrades, enchants and sockets, an XP-based crafting system, and a full spell & skill layer. Everything runs on ESX Legacy, QBCore and Qbox through auto-detecting bridges.

rklequipment — gear, stats, combat rklforge — upgrade · enchant · socket rklcrafting — recipes & XP spell system — 5 magic resources effects & FX — status & particles rklinterface — HUD & class build rklhalloween — Hallowed Night seasonal event

Overview

Each resource is independent but they share data. The forge reads and writes the equipment metadata, so equipment is the core the others build on.

ResourceDoesOwns
rklequipmentEquip gear, apply stats, durability, combat combosplayer_equipment
rklforgeUpgrade / enchant / socket equipped gearedits equipment metadata
craftingCraft items, levels & XPslv_crafting_data
Load order matters

The forge edits equipment metadata directly, so it must start after equipment. Full order is in the next section.

Install & server.cfg

Required on every framework

ox_lib, ox_inventory, and oxmysql. No es_extended is required for QBCore/Qbox — the bridge detects the framework automatically (qbx_core → Qbox, qb-core → QBCore, es_extended → ESX Legacy).

Ensure order

server.cfg
ensure oxmysql
ensure ox_lib
ensure ox_inventory

# your framework (one of)
ensure es_extended      # or qb-core / qbx_core

ensure rklequipment     # core — start first
ensure rklforge         # AFTER equipment
ensure rklcrafting
ensure rklskilltree     # class XP / skill nodes
ensure rklbinder        # card binder (uses forge_card)
ensure rklrepair        # durability repair NPC

# effects (needed for combat visuals & damage numbers)
ensure rklparticleseffect
ensure rklstatuseffect

# spell system
ensure rklgrimoire
ensure rklskillsystem
ensure rklspellmanage
ensure rklspellbook
ensure rklskillcheck

# HUD (reads skilltree + forge)
ensure rklinterface

Currency — pick what players pay with

Costs that the scripts call "awaken coin" are not hard-wired to an item. Set Config.RKLCurrency in the resource's config.lua (an open file, editable under escrow) and the bridge routes every charge and balance check for you — same behaviour on ESX Legacy, QBCore and Qbox.

config.lua
Config.RKLCurrency = { type = 'item', item = 'awaken_coin' }  -- ox_inventory item
-- Config.RKLCurrency = { type = 'money' }                     -- cash
-- Config.RKLCurrency = { type = 'bank'  }                     -- bank balance
-- Config.RKLCurrency = { type = 'account', account = 'black_money' }
typeESX LegacyQBCore / Qbox
itemox_inventory itemox_inventory item
moneygetMoney()money.cash
bankgetAccount('bank')money.bank
accountnamed ESX accountnamed money type
Leaving it out is safe

If Config.RKLCurrency isn't defined, nothing changes: an ESX server's own getAwakenCoin() is used when it exists, otherwise the awaken_coin ox_inventory item. Defining it always wins, so your choice is honoured on every framework.

Per-shop currency in rklequipment

Equipment shops already choose their own currency with currencyType in Config.Shops — set it to money, bank, any ox_inventory item name, or awaken_coin to follow the Config.RKLCurrency setting above.

Resource names

Exports and cross-resource events use fixed names, and a FiveM export only resolves if the folder name matches the caller. The whole suite is branded rkl* — keep these folder names exactly:

Folder nameUsed by
rklequipmentexports['rklequipment'] · rklequipment:* events
rklforgeexports['rklforge'] · rklforge:* events
rklcraftingrklcrafting:* events & callbacks
All references are rkl

Every export, event, callback and cross-resource sync uses the rkl names above, matching the folders. NUI uses GetParentResourceName(), so the UI follows the folder name automatically. The database tables (player_equipment, slv_crafting_data) keep their original names so existing data is untouched.

Optional integrations

Three resources outside this suite are used when present: rklzones (safe zones), rklcompanion (pet detection) and rklspawnmonster (monster lookup). rklskilltree and rklforge are optional to each other in the same way.

Every one of these calls is wrapped, so a missing resource can never throw. You can also switch them off explicitly:

config.lua
Config.Integrations = {
    ['rklzones']        = true,  -- fallback: never in a safe zone
    ['rklcompanion']    = true,  -- fallback: not a companion
    ['rklspawnmonster'] = true,  -- fallback: no monster
    ['rklskilltree']    = true,  -- fallback: level 0
}
ValueBehaviour
trueUse it, but only when the resource is actually started
falseNever call it — the fallback value is used
omittedSame as true, so older configs keep working

Shared state bag

LocalPlayer.state.playerClass (and playerSubclass) is how the player's class travels between resources. rklskilltree sets it; rklinterface and rklequipment read it. It is framework-independent, so it behaves the same on ESX, QBCore and Qbox.

Start order matters

rklforge writes to equipment metadata and rklinterface reads forge stats, so start rklequipment first, then rklforge, then the rest. The full order is in Install & server.cfg.

Character class columns

The skill tree stores the class, sub-classes and rank on the character row. Run the block that matches your framework — the SQL file has both, with the QBCore/Qbox one commented out.

ESX Legacy
ALTER TABLE `users`
    ADD COLUMN IF NOT EXISTS `class`       VARCHAR(64) DEFAULT NULL,
    ADD COLUMN IF NOT EXISTS `sub_classes` TEXT        DEFAULT NULL,
    ADD COLUMN IF NOT EXISTS `rank`        VARCHAR(8)  DEFAULT 'E';
QBCore / Qbox
ALTER TABLE `players`
    ADD COLUMN IF NOT EXISTS `class`       VARCHAR(64) DEFAULT NULL,
    ADD COLUMN IF NOT EXISTS `sub_classes` TEXT        DEFAULT NULL,
    ADD COLUMN IF NOT EXISTS `rank`        VARCHAR(8)  DEFAULT 'E';
The identifier column

Scripts store whatever the bridge returns — the ESX identifier on ESX Legacy, the citizenid on QBCore/Qbox. Both fit VARCHAR(64), so no schema change is needed per framework. Moving frameworks on the same database means old rows won't match, which is normal for any migration.

Open files — combos & language

Two files ship outside the escrow so server owners can edit them with the resource still encrypted. Both are listed in escrow_ignore.

language.lua

Every player-facing string lives in a Lang table. Translate values freely; keep any %s placeholder — it's filled at runtime (for example the item name in a "broke" message).

language.lua
['armor_broken_desc'] = 'Your %s broke! Its bonus stats are gone.',

The helper is called _L('key') (not _U) so it never clashes with ESX's built-in translator.

combos.lua

Each weapon type's attack animation sequence is data only — change the dictionary, clip, timing or number of stages without touching logic.

combos.lua
Config.Combos.Katana = {
    [0] = {dict = 'kp_wm_gs_slash_01', anim = 'kp_wm_gs_slash_01_clip', wait = 700, next = 1},
    [1] = {dict = 'kp_wm_gs_slash_02', anim = 'kp_wm_gs_slash_02_clip', wait = 700, next = 2},
    -- last stage loops back with next = 0
}

Built-in types: BigSword, Staff, Unarmed, DualDagger, Katana, DualKatana.

Add a brand-new weapon type

The combo dispatch is data-driven: any weapon type that isn't built in is played by the generic runner — no escrowed edits needed.

  1. Give the weapon item w_type = "yourtype" in config.lua.
  2. Define Config.Combos.yourtype in combos.lua.
combos.lua — custom type
Config.Combos.spear = {
    [0] = {dict = 'melee@large_wpn@streamed_core', anim = 'plyr_takedown_front_attacker',
           wait = 900, flag = 1, next = 1, sound = 'hitflesh', damageRange = 2.5},
    [1] = {dict = 'melee@large_wpn@streamed_core', anim = 'plyr_takedown_rear_attacker',
           wait = 1100, flag = 1, next = 0, freeze = true,
           vfx = {dict = 'scr_sum2_hal', part = 'scr_sum2_hal_rider_weak_green',
                  attachType = 'weapon_tip', loop = true,
                  color = {r = 0.2, g = 0.6, b = 1.0}, scale = 0.5, duration = 700,
                  off = {x = 0.0, y = 1.0, z = 0.0}}},
}

Optional per-stage fields

flag, freeze, blendIn, blendOut, wait, next, sound, damageRange, and vfx (a particle table — add weapon-tip effects straight from the open file).

Optional per-type tuning

combos.lua
Config.ComboSettings = {
    spear = { speedFactor = 0.03, speedCap = 0.30, minWait = 300, comboTimer = 5, slot = 'right_hand' },
}
Built-ins are untouched

The six built-in combos keep their own hand-tuned behavior (Staff casts priest/mage effects, DualDagger freezes, BigSword has VFX + attack speed). The generic runner is used for custom types only.

Effects & FX

Two shared layers used across combat and magic: a status-effect system (poison, burn, slow, blind, stun, freeze) with screen and world VFX, and a particle / damage-number layer that other resources fire to show hits and effects.

Shared by the suite

The FX layer handles rkldamageped:victim — the same event the equipment combos fire to damage NPCs and show floating numbers. Keep it running or combat visuals won't appear.

---ox_inventory calls exports.rklhalloween:useItem instead (see install/items/ox_inventory.lua).
function Bridge.RegisterUsable(item, cb)
    local inv = Bridge.Inventory
    if inv == 'ox_inventory' or inv == 'internal' then
        return
    end
    if Bridge.Framework == 'qb' then
        QBCore.Functions.CreateUseableItem(item, function(source) cb(source) end)
    elseif Bridge.Framework == 'qbx' then
        exports.qbx_core:CreateUseableItem(item, function(source) cb(source) end)
    elseif Bridge.Framework == 'esx' then
        ESX.RegisterUsableItem(item, function(source) cb(source) end)
    end
end

  • The block is based on the curse's full duration. A curse lifted early by death still keeps new curses away until duration + CurseImmunityAfterCurse has passed.
  • The Purifying Elixir lifts all curses and replaces the block with its own Config.Potions.hn_potion_purify.immunity (180 seconds).
  • If no enabled curse is allowed (for example, every curse is disabled), no curse lands. A trick still pays its Souls.

Before you edit

  • The config files load as shared scripts (server and client) when the resource starts, so restart the resource after you change them.
  • Each module has its own Enabled switch. Setting it to false turns that module off on both server and client.
  • Lanterns, doors, gathering nodes and cauldrons only exist while the season is active (Config.Season in config/config.lua). Scheduled Haunted Nights also wait for the season. An admin start (/hnhaunt start or the StartHaunt export) works at any time.

One press of the interact key starts it; the key doesn't have to be held. The server also allows a little extra distance on top of each InteractDistance, because client-side ground snapping can shift positions slightly.

How a brew resolves

  1. Opening the cauldron asks the server for the recipe list. The server checks the season, Hooks.CanParticipate and that the player is at a cauldron, then sends each recipe with the player's ingredient counts.
  2. With Minigame.Enabled, the stir ring opens. Players press SPACE (or click anywhere in the stir window) while the marker is inside the glowing zone. Pressing Esc during the stir cancels it, and nothing is brewed or used up.
  3. The server checks the ingredients again. Success: the ingredients are removed, the player gets the result item and Souls. Fail: the player gets Fail.Item, and the ingredients are removed only if Fail.LoseIngredients is on.
  4. If the result item doesn't fit in the inventory, every removed ingredient is given back.

Hallowed Night — Player guide

What a player sees and does in every activity, step by step. It's written so you can copy it into your own server guide or Discord. All numbers are the defaults from the config files, so if you change a value, update the matching line here too.

Getting started

  • When: the event runs during the Halloween season, by default from 15 October to 3 November (server date). Outside the season the lanterns, doors, gathering spots and cauldrons are gone, and actions answer with "The veil is closed. Come back during the Halloween season."
  • Your menu: type /halloween or press F7 to open the Grimoire (profile, leaderboard, rewards, recipes, curses).
  • Souls are the event score, and every activity gives some. Each time your Souls change, a small pill in the lower right of the screen shows your new total and how many you just gained.
  • Interacting: walk up to a lantern, door, plant or cauldron. A glowing prompt appears at the bottom of the screen (for example E Collect Soul Lantern). Press E. On servers that use a target eye (ox_target or qb-target), pick the option from the target menu instead.
  • Timed actions: collecting, knocking and gathering show a flaming progress ring that fills on its own. You stand still while it runs. Press X to cancel. Dying, getting ragdolled or entering a vehicle also cancels it.
  • You can't interact from inside a vehicle or while you're dead.

5. Brewing at the Witch's Cauldron

6. Haunted Night

A server-wide event. By default it starts at 20:00 and 23:30 server time during the season (when at least one player is online), or whenever an admin starts it. The Grimoire's profile tab shows when the next one is due.

  1. The warning. Everyone gets a banner, "The Veil Thins: Spirits gather at Pacific Bluffs Cemetery in 2m 00s", with a deep bell. A flashing blip and a coloured circle mark the zone on the map.
  2. Head to the zone. Inside the circle the weather turns to Halloween with heavy fog, a low drone plays and tombstones rise around the area. A panel on the right side of the screen shows the zone name, Wave, Spirits left and Time left (during the warning, that's the countdown to the start).
  3. It begins. Banner: "Haunted Night: Defend <zone> from the restless dead!" The blip stops flashing and you have 15 minutes. (Only the warning banner goes to everyone. This one and the later banners show for players within about 600 m of the zone, and the wave messages within about 400 m.)
  4. Three waves of spirits. A "Wave 1 / 3" message, then 6, 9 and 12 ghostly, staggering spirits attack. Player FAQ

  • I can't find anything, and the Grimoire says "The veil is closed". The Halloween season isn't active on the server right now.
  • The prompt doesn't show up. Get out of your vehicle, and make sure you aren't dead or already doing something. Prompts are hidden while a menu is open.

Ground snapping

Lanterns, gathering nodes, cauldrons and tombstones are props. The pack looks for the ground just above the saved height (2 m, then 10 m, then 50 m higher) and settles the prop on it, so standing on the spot is enough. The server still checks the player's distance against the saved position (it allows the interact distance plus a little extra sideways, and roughly 15 m more than that up or down), so a spot saved far above or below where players stand ends in "You are too far away." Doors and zone centres aren't props: they use the height exactly as copied.

Door heading

When a player knocks, they're turned to face heading + 180 (towards the door), and the neighbour appears 1.15 m in front of them, facing back at them. The easy way: stand on the doorstep with your back to the door, facing where the neighbour should look, and run /hncoords. If you copied it while facing the door, add 180 to the heading (subtract 360 if the result is above 360).

config/trickortreat.lua
Doors = {

    -- ... the existing doors ...
    vec4(-1150.25, -1525.10, 4.35, 212.4),    -- copied with my back to the door
},

2. Change rewards and loot tables

There are two kinds of loot table:

  • Rolled (chance): every line is rolled on its own, chance is a percentage from 0 to 100 (100 if you leave it out). Used by Config.Lanterns.Loot, Config.Lanterns.CursedLoot and the Haunted Night items lists.
  • Weighted (weight): exactly one line is picked, with odds equal to its weight divided by the total. Used by Config.TrickOrTreat.Treats.

  • Keep them in ascending order. The Grimoire's progress bar runs up to the last milestone's Souls.

7. Run the lantern hunt in personal (collectible) mode

In 'personal' mode every location in Locations is a collectible: each player can claim each spot once per season, at their own pace, with no race. Lanterns a player already took stay hidden for that player only.

config/lanterns.lua
Config.Lanterns = {
    Enabled = true,
    Mode = 'personal',
    -- ActiveCount and RespawnSeconds are ignored in personal mode
    CursedChance = 0.15,
    CursedLooksDifferent = true,
    Blips = {
        Enabled = true,             -- optional: a map blip on every lantern the player still needs
        Sprite = 484, Color = 47, Scale = 0.6,
    },
    -- ... the rest of the file unchanged ...
}
  • Which lanterns are cursed is fixed per location in personal mode (worked out from the spot's number and CursedChance), so the same spots are cursed for everyone.
  • Progress is saved with the player's season data. A new Config.Season.Id resets the collection.
  • /hnlanterns respawn is meant for global mode. In personal mode every location is always listed anyway.
  • Add plenty of locations: with 32 spots, a dedicated player finishes quickly. Remember to add new spots at the end of the list (see tutorial 1).

Hallowed Night — Exports, state & hooks

You can connect Hallowed Night to the rest of your server in three ways. Exports can be called from any other resource. State bags let any script read the live season and event state. Hooks and the bridge are small open Lua files inside rklhalloween that stay editable after escrow. You edit them to plug the pack into your framework, logs, notifications and weather script. Always call exports as exports['rklhalloween'], which is why the folder name must stay rklhalloween.

Haunted Night exports need the module enabled

StartHaunt, StopHaunt and GetHauntState are registered by the Haunted Night module. If you set Config.Haunted.Enabled = false, they don't exist and GlobalState.hnHaunt is never set. Calling a missing export throws an error, so wrap the call in pcall if your script might run with the module turned off. Every other export is always available.

Hooks.CanParticipate(src)Server

Return false to block a player from all Halloween activities (jail, admin duty and so on). The default returns true.

  • Season-gated actions (lanterns, door knocks, gathering, opening the cauldron and brewing) check it at the start and again when the action finishes. Here any falsy value blocks, so always return true or false, never nil.
  • Event rewards (spirit kills, Hollow King rewards, specter rewards) and milestone claims check it without the season gate, so admin-started events work out of season too. Here only an explicit false blocks.
  • It isn't checked for opening the Grimoire, using consumables, the exports or admin commands.

Blocked players get "You can't do that right now." for actions. Event rewards are skipped and milestone claims fail without a message.

Hallowed Night — Data, persistence & security

Hallowed Night needs no SQL. Player progress is stored in the resource KVP (key-value storage) of rklhalloween, which only the server can read or write. This page explains what is stored, when it is saved, how to start a fresh season, and everything the server checks before it hands out a reward.

Where progress lives

Each player has two keys per season:

KeyContent
hn:<season>:p:<id>Full progress as JSON (all fields below)
hn:<season>:s:<id>Small summary {"n": name, "s": souls}, so the leaderboard can be built without reading every full record

<season> is tostring(Config.Season.Id) (default '2026'). <id> is whatever Bridge.GetIdentifier returns:

FrameworkIdentifierExample key
Qbox / QBCorePlayerData.citizenid, so progress is per characterhn:2026:p:ABC12345
ESX LegacyxPlayer.identifier, as ESX gives it (per character on multicharacter)hn:2026:p:<esx identifier>
Standalonethe player's license: identifier, so progress is per accounthn:2026:p:license:1a2b…
No identifier, no progress

If the bridge returns nil (for example, the player is still on the character selection screen), the player can't do any Halloween activity and the Grimoire shows "You can't do that right now." Progress loads the first time the server needs it, for example on the player's first action or when they open the Grimoire.

Every field is type-checked when it loads. Broken or missing values fall back to defaults, and claims for milestone indexes that no longer exist are dropped.

What is not saved

These live only in server memory and reset when the resource restarts:

  • Per-door trick-or-treat cooldowns. They're keyed by identifier, so reconnecting doesn't reset them, but a resource restart does. The daily counter is saved.
  • Curse blocks and immunity, and specter reward tokens.
  • Which global lanterns are active, and the spots that are cooling down. They're picked again at random on start.
  • Harvested gathering nodes.
  • A running Haunted Night. A restart ends it and deletes its spirits.
  • The leaderboard cache.

When it saves

MomentWhat happens
Every 30 sAll changed (dirty) players are written and the KVP is flushed to disk

Crashes

A clean stop or restart rklhalloween saves everything. If the server crashes or the process is killed, changes made since the last 30-second save can be lost. Milestone claims are never lost this way because they're written immediately.

Leaderboard

The leaderboard is built when someone opens or refreshes the Grimoire. The server scans every hn:<season>:s: key, keeps players with more than 0 Souls (offline players included), sorts them by Souls and caches the result for Config.Leaderboard.CacheSeconds. The top Config.Leaderboard.Size entries are sent as name + Souls only, so identifiers never reach players. Each player's own rank and the total player count come from the same cache, so a rank can be up to CacheSeconds old. The Souls number in the profile is always live.

config/config.lua
Config.Leaderboard = {
    Size = 10,           -- entries shown in the Grimoire
    CacheSeconds = 60,   -- how long one scan is reused
}

New season & wipes

  1. Change Config.Season.Id (for example to '2027') and update Start / Finish if needed.
  2. Restart the resource. The season id is read once at start.

Everyone starts at 0 Souls with a fresh leaderboard, fresh milestones and fresh personal lanterns. Nothing is deleted: the old season's keys stay in the KVP under the old id, so setting the id back brings the old progress back.

Changing lists mid-season

Claimed milestones and personal-mode lanterns are stored by index. During a running season, add new entries to the end of Config.Milestones and Config.Lanterns.Locations, and don't reorder or remove existing ones. Otherwise saved claims point at the wrong milestone or spot. Door cooldowns are keyed by door index too.

  • Reset one player's Souls: /hnsouls <id> -<amount> (Souls stop at 0). Stats and claimed milestones stay.
  • Switching frameworks changes the identifiers (citizenid vs ESX identifier vs license), so players start empty. Their old keys are still stored.
  • Removing one player completely has no built-in command. If you need it, add a console command to editable/server/hooks.lua. It runs inside rklhalloween, so it can reach the pack's KVP:
editable/server/hooks.lua: optional console command (not built in)
-- usage (server console): hnwipe <identifier>   e.g. hnwipe ABC12345
-- only use it while that player is OFFLINE: an online player's cached progress can be written back
RegisterCommand('hnwipe', function(src, args)
    if src ~= 0 then return end                         -- console only
    local id = args[1]
    if not id then return print('usage: hnwipe <identifier>') end
    local season = tostring(Config.Season.Id)
    print(GetResourceKvpString(('hn:%s:p:%s'):format(season, id)) or 'no data')   -- what is being removed
    DeleteResourceKvp(('hn:%s:p:%s'):format(season, id))
    DeleteResourceKvp(('hn:%s:s:%s'):format(season, id))
    print(('[rklhalloween] wiped %s for season %s'):format(id, season))
end, false)

Backups & moving servers

  • The FiveM server (FXServer) stores resource KVP in its own database, the db folder in the directory the server runs from (normally your server data folder). Back that folder up along with the rest of your server data. The best time is while the server is stopped, or right after a clean resource stop, which flushes every pending save.
  • Restoring the folder restores everyone's Souls, stats, claims, satchels and daily counters for every season id.
  • KVP belongs to the resource name, so a renamed folder starts with empty storage. That's one more reason to keep the folder name rklhalloween.
  • To move to a new host, copy the db folder together with the resource and keep the same framework, so the identifiers still match.

Yes. Hallowed Night is a free release delivered through FiveM Asset Escrow: a Tebex package at price 0 that players claim into their keymaster Granted Assets (see Tebex & escrow). Only the gameplay code in client/, server/ and shared/ is encrypted. Everything you need to customise stays open:

Does it need SQL?

No. Progress lives in server KVP, so there is no database table to import. Each player has two keys: hn:<Season.Id>:p:<identifier> (Souls, stats, claimed milestones, collected lanterns, satchel contents, daily knock count) and hn:<Season.Id>:s:<identifier> (name and Souls, used by the leaderboard). Changed data is written every 30 seconds, when a player leaves or switches character, right after a milestone claim, and when the resource stops. install/items/esx.sql only registers the items for the ESX default inventory. It has nothing to do with progress.

Which frameworks and inventories are supported?

Everything is auto-detected when the resource starts. The first match wins:

Frameworkqbx_core → qb-core → es_extended → standaloneConfig.Framework
Inventoryox_inventory → qb-inventory (on QBCore/Qbox, includes the ps/lj forks) → ESX default → internal satchelConfig.Inventory

OneSync is required: the manifest lists '/onesync' as a dependency, because Haunted Night spirits are created by the server. The server console prints what was detected on every start, for example [rklhalloween] framework: qb | inventory: qb-inventory.

Is progress saved per character?

Yes, on frameworks. The identifier is the citizenid on Qbox/QBCore and the ESX identifier on ESX, so every character has its own Souls, milestones and satchel. Character switches are handled through QBCore:Server:OnPlayerUnload and esx:playerLogout. On standalone the player's license is used, so there is one profile per license.

Can I rename the resource folder?

Keep it rklhalloween. The UI finds its own name automatically, but two things are written with the fixed name: the ox_inventory item lines (server = { export = 'rklhalloween.useItem' }) and any exports['rklhalloween'] calls in your other scripts. If you rename the folder anyway, update both or potions stop working on ox_inventory.

Yes, through Hooks.StandaloneAddMoney(src, account, amount) in editable/server/hooks.lua. How do I reset the leaderboard?

Change Config.Season.Id (for example '2026' → '2027') and restart the resource. All KVP keys include the season id, so everyone starts from zero: Souls, stats, milestones, collected lanterns, daily knocks and the built-in satchel (used when Config.Inventory resolves to 'internal', which is what auto-detection picks on standalone without ox_inventory). The old season's data stays in KVP under the old id, so switching back to it brings it back.

To take one player off the board, use /hnsouls [id] -[amount] while they are online: Souls stop at 0, and players with 0 Souls are not listed.

Gameplay & balancing

Can I change the boss model or HP?

Yes, everything about The Hollow King is in Config.Haunted.Boss. His HP is Health + HealthPerPlayer × (participants − 1), counted when he spawns, and capped at 8000.

config/haunted.lua (excerpt)
Boss = {
    Label = 'The Hollow King',          -- banner and boss bar name
    Model = 'u_m_y_zombie_01',          -- any ped model
    Health = 4000,                      -- HP with one participant
    HealthPerPlayer = 1200,             -- added for every extra participant
    Weapon = 'WEAPON_BATTLEAXE',
    HeadModel = 'hn_pumpkin_head',      -- set this and HeadFallback to false for no pumpkin head
    HeadFallback = 'prop_veg_crop_03_pump',
    Nova = { interval = 18, radius = 7.0, damage = 15 },
    Summon = { atHealth = { 0.66, 0.33 }, count = 4 },
    -- ...
},

Two things to know: the boss's pumpkin head uses the same Config.Curses.pumpkin_head.offset as the curse, so a ped with a different skeleton may need that offset adjusted. And the Soul Nova message in the locale files (haunt_nova) names "The Hollow King" directly, so update it if you rename him.

Why is the boss HP capped at 8000?

GTA syncs ped health in 13 bits, so the highest value every client agrees on is 8191. The server caps the boss at 8000 (a fixed limit in the escrowed server code, not a config key), and the owning client applies HP + 100, also clamped to 8191. With the default values, the cap is reached at 5 participants (4 players give 7600). To make him harder for big groups, use the other settings: a shorter Boss.Nova.interval, a bigger Nova.damage or Nova.radius, more Summon.atHealth thresholds or a higher Summon.count, or a shorter Config.Haunted.TimeLimit.

Can I add more doors, lanterns and other locations?

Yes. The code has no limit on any list. Stand at the spot and type /hncoords: it copies vec4(x, y, z, heading) to your clipboard and prints it in F8. Then paste it into the right list and restart the resource.

In Mode = 'personal', collected lanterns are saved by their position in the list. Add new locations at the end. Removing or reordering entries changes which spots players have already collected this season.

Can I remove curses from trick-or-treat?

  • No tricks at all: Config.TrickOrTreat.TrickChance = 0. Every knock is a treat.
  • Only some curses: set enabled = false on any curse in Config.Curses, or lower its weight. Disabled curses also disappear from the Grimoire's curse list.
  • No cursed lanterns: Config.Lanterns.CursedChance = 0.

If every curse is disabled but TrickChance is above 0, tricks still happen: the player gets the Trick message and Souls.trick, but no curse lands. Use TrickChance = 0 if you don't want tricks at all.

Can every player collect every lantern?

Yes: set Config.Lanterns.Mode = 'personal'. Every location becomes a collectible that each player can claim once per season, and ActiveCount / RespawnSeconds no longer apply. The default 'global' keeps ActiveCount (20) shared lanterns on the map, which the first player to finish collecting takes.

Hallowed Night — Troubleshooting

Common problems, each with the cause and the fix. Start with the quick checks: they solve most problems on their own.

Quick checks

  1. Read the startup line. Every start, the server console prints the detected framework and inventory. If it says standalone / internal on a framework server, see Wrong framework or inventory detected.
  2. Look for [rklhalloween] errors. Callback failures and spirit spawn failures print in the server console, and curse errors print in F8, even with debug off.
  3. Turn on Config.Debug to log every rewarded action (see Debug mode at the bottom).
server console
[rklhalloween] framework: qbx | inventory: ox_inventory

Season & startup

"The veil is closed" / nothing spawns

The season is off, so no lanterns, doors, nodes or cauldrons are created, and every rewarded action replies with this message. Config.Season is compared with the server's local date, so a host in another time zone can open or close a day off. The state is checked on start and every 5 minutes. For testing, set Config.Season.AlwaysOn = true and restart the resource.

Wrong framework or inventory detected

Detection runs once, when rklhalloween starts. If your framework starts after it, the pack runs as standalone: progress is saved per license instead of per character, money goes through Hooks.StandaloneAddMoney, and potions aren't registered as usable with your framework. Inventory detection works the same way: if ox_inventory starts later, the pack falls back to the framework's inventory (qb-inventory or ESX), or to the built-in satchel when no framework was found either. Move ensure rklhalloween below your framework, inventory and target resources, or force the choice with Config.Framework / Config.Inventory.

"You can't do that right now."

The server couldn't get an identifier for the player (the character isn't loaded yet), or Hooks.CanParticipate(src) returned false. The Grimoire shows the same message when there's no identifier. Check the character is fully loaded and review any rules you added to that hook.

Props & items

Props show as vanilla fallbacks

The custom models didn't load, so each config's fallback is used (plain pumpkins, a barrel, plants, bin bags, gravestones). Check that:

  • stream/ contains the nine hn_*.ydr files and hn_props.ytyp.
  • fxmanifest.lua still has data_file 'DLC_ITYP_REQUEST' 'stream/hn_props.ytyp' and 'stream/hn_props.ytyp' in files.
  • You did a full server restart after adding or replacing streamed files. restart rklhalloween is not enough.

The candy bucket has no fallback: if it can't load, the NPC simply holds nothing.

Potions do nothing on ox_inventory

Each usable item (the seven potions, hn_candy and hn_sludge) needs server = { export = 'rklhalloween.useItem' }, as in install/items/ox_inventory.lua. Without it, ox_inventory has nothing to call. The export also only accepts items that have an entry in Config.Potions, so an item you removed there can't be used. If you renamed the folder, the export string must use the new name. Restart the server after editing ox_inventory items.

Potions do nothing on QBCore, Qbox (without ox) or ESX

On start, the pack registers every item in Config.Potions as usable with the framework (QBCore.Functions.CreateUseableItem, exports.qbx_core:CreateUseableItem or ESX.RegisterUsableItem). Registration is skipped when the framework wasn't detected (start order), or when the inventory is ox_inventory or internal. On QBCore, the item must also have useable = true, which install/items/qb-core.lua already sets.

Items broken in qb-core (paste format)

install/items/qb-core.lua uses the hn_item = { name = 'hn_item', ... }, format. Paste every line inside the QBShared.Items = { ... } table in qb-core/shared/items.lua, before its closing brace, and keep the comma at the end of each line. Don't paste the ox_inventory file into qb-core (or the other way round), and don't wrap the lines in a second table. A Lua syntax error stops that file from loading. Typical symptoms are "You can't carry that." on every reward and missing icons. For icons, copy install/images/*.png to qb-inventory/html/images/.

qb-core/shared/items.lua
QBShared.Items = {
    -- ...your existing items...

    hn_mandrake_root = { name = 'hn_mandrake_root', label = "Mandrake Root", weight = 50, type = 'item', image = 'hn_mandrake_root.png', unique = false, useable = false, shouldClose = true, description = "A gnarled root that screams when pulled. Hums with earthy magic." },
    -- ...the rest of install/items/qb-core.lua...
}

"You can't carry that." (qb-inventory and others)

The inventory refused the item: it's full or over weight, or the item isn't registered. On qb-inventory, rewards are added with Player.Functions.AddItem, and this message shows when it returns false. Milestone claims check for space first, with qb-inventory 2.x CanAddItem (on older qb-core and the forks: the player's total weight against QBCore.Config.Player.MaxWeight). On ox_inventory the check is CanCarryItem, and on ESX canCarryItem. What happens next depends on the activity:

Interaction & UI

The E prompt doesn't show

  • Wrong mode: the prompt only runs when Config.Interaction = 'prompt', or 'auto' with no target resource running.
  • Blocked by ClientHooks.CanInteract(): by default, players in any vehicle can't interact, and neither can dead or downed players while Config.DisableWhileDead = true (it checks QBCore isdead/inlaststand metadata, Qbox isDead/inLastStand state and the ESX death event). Any rule you add to that hook applies too.
  • Busy: another hold action is running, or a Halloween panel is open.
  • Too far: players must be within InteractDistance (lanterns 2.0, doors 1.8, nodes 1.8, cauldrons 2.2). Doors are not snapped to the ground, so the exact z counts. Record doors with /hncoords while standing where the player should stand.
  • Nothing to interact with: the season is closed, the node was already gathered (it comes back after respawn seconds), Moonpetal only shows from 20:00 to 06:00 in-game, or someone else took the lantern.

The keys are Config.InteractKey (control 38, E) and Config.CancelKey (control 73, X).

ox_target / qb-target option is missing

  • The default is the custom prompt. Set Config.Interaction = 'ox_target' (or 'qb-target' / 'auto'), and start the target resource before rklhalloween ('auto' only looks once, at start).
  • Lanterns, nodes and cauldrons are entity targets, added only once the prop has spawned (within its RenderDistance). They all have collision (box or custom mesh), so the target raycast can hit them. Doors are sphere zones (radius 1.2) at the door's vec4, so aim at that exact spot.
  • hn_pumpkin_head and hn_candy_bucket have no collision. That's expected: they're never targets.
  • The same ClientHooks.CanInteract() rules apply: no options in a vehicle, while dead, or during another action. The option distance is the feature's InteractDistance.
  • Config.Debug = true draws the door zones so you can see where they are.

The UI is stuck or the cursor won't go away

Press ESC: it closes the Grimoire and the cauldron. During the stirring minigame, the first ESC cancels the stir (nothing is used up) and the second one closes the window. While a brew is finishing (Config.Cauldron.BrewTime, 3500 ms), ESC is ignored until the result shows. If it's still stuck, run restart rklhalloween in the server console: stopping the resource releases the UI focus.

The Grimoire doesn't open

It's /halloween (Config.Menu.Command), with F7 as the default key (Config.Menu.Key, '' = no key). Changing the key only changes the default, and players who rebound it in FiveM's key settings keep their own key. It won't open while another Halloween panel is open, and it shows "You can't do that right now." if the server has no identifier for the player yet.

Haunted Night

Spirits never appear

  • OneSync must be on. The resource depends on /onesync.
  • Someone must be in the zone. Waves wait until a player is within the zone radius plus Config.Haunted.ParticipantRadius (30 m). That player's client finds the ground positions.
  • Custom zones: the host's client only picks ground points within 25 m of the zone center height, not on water, and 5 to 90 m (flat distance) from the host player, so keep center.z at ground level (use /hncoords).
  • Cap: at most MaxAlive (14) spirits are alive at once. The rest arrive as others die.
  • Check the server console for [rklhalloween] spawn failed.

"A Haunted Night is already running." / the event looks stuck

Only one event can run at a time. It counts as running while it is announcing, active or in the boss phase, and for about 12 seconds after it ends. A wave only ends when all its spirits are dead. If players leave, the spirits retreat on their own once Config.Haunted.TimeLimit (900 seconds) runs out. To end it right away, use /hnhaunt stop (or hnhaunt stop in the server console, or the StopHaunt export). It deletes every spirit and resets the state.

It doesn't start on schedule

Config.Haunted.Schedule uses the real server clock (24h), checked every 20 seconds. A scheduled start also needs an active season, at least MinPlayers (1) online, and no event already running. An empty Schedule means admin-only. /hnhaunt start [zone] works any time, even out of season.

The boss HP stops growing with more players

That's the 8000 HP cap: GTA syncs ped health in 13 bits. With the defaults, it's reached at 5 participants. See the FAQ for other ways to make the fight harder.

Weather & time

Weather flickers inside the zone

A weather sync script is fighting the HALLOWEEN override. With Config.Haunted.Visuals.PauseWeatherSync = true, ClientHooks.OnHauntZone pauses qb-weathersync and Renewed-Weathersync while the player is inside, and resumes them when they leave. For any other sync script, add its own pause/resume call to that hook, or set Visuals.Weather = '' and keep only the fog timecycle (Visuals.Timecycle).

The clock jumps when entering the zone

Pausing qb-weathersync also sets the clock to 18:00, so the hook saves the current time and puts it back right away. When the player leaves, the sync script takes over again and the clock follows the server time. If another script still changes the time inside the zone, it isn't covered by the hook: add it to ClientHooks.OnHauntZone, or turn off PauseWeatherSync and set Visuals.Weather = ''.

Curses & effects

"Your purification repelled a curse." / curses don't land

After every curse, the player is immune for the curse's duration plus Config.CurseImmunityAfterCurse (20 seconds). The Purifying Elixir grants Config.Potions.hn_potion_purify.immunity (180 seconds). Both show this same message. Only enabled curses are picked, and in a vehicle only curses with vehicle = true can land (by default only pumpkin_head). If no curse fits, nothing lands.

The pumpkin head is misaligned

Adjust Config.Curses.pumpkin_head.offset. The config suggests changing x between -0.06 and -0.09 (default -0.075) to raise or lower it. It's attached to bone 31086 (SKEL_Head). Leaderboard & progress

The leaderboard isn't updating

It's rebuilt at most once every Config.Leaderboard.CacheSeconds (60), when someone opens the Grimoire (claiming a milestone or using a satchel item reloads it too), and the rank on the Profile tab comes from the same cache. Players with 0 Souls are not listed, and Config.Leaderboard.Size (10) sets how many rows show. Close the Grimoire and reopen it after a minute.

The leaderboard shows last season's players

Change Config.Season.Id and restart. Old progress stays in KVP under the old id. If you use the built-in satchel ('internal' inventory), its contents start empty too.

Door cooldowns or lanterns reset after a restart

Expected. Door cooldowns, the global lantern layout and gathered nodes are kept in memory, so a resource restart clears them. Saved progress (Souls, stats, milestones, personal-mode lanterns, satchel and the daily knock count for DailyLimit) is in KVP and stays. In global mode, /hnlanterns respawn reshuffles the lanterns at any time.

Milestone or lantern money isn't paid on standalone

Standalone has no money system. Fill in Hooks.StandaloneAddMoney in editable/server/hooks.lua and return true (see the FAQ), or remove the money rewards.

Language

Tagalog or another locale isn't applied

  • Config.Locale must match the table key exactly ('tl' for Locales['tl']). Restart the resource after changing it.
  • A new locale file must be loaded, either listed in fxmanifest.lua shared_scripts or pasted into an existing locale file.
  • Missing keys fall back to English one by one, but the ui = { ... } table is used as a whole. A locale without it shows the English UI.
  • Curse names, item names, milestone, zone and boss labels and the Souls label come from config/, not from the locale files. Translate them there.

Loot luck from equipped gear

Boost a drop chance using the player's total luck (server side):

your loot script — server
local function rollDrop(src, baseChance)
    local luck = exports['rklforge']:GetPlayerLuck(src) or 0
    local chance = math.min(100, baseChance + luck * 0.5)
    return math.random(100) <= chance
end

Troubleshooting

An export returns nil

The folder name must match the export call — see Resource names. exports['rklequipment'] only works if the folder is rklequipment.

Forge doesn't apply stats to gear

Check the ensure order — the forge must start after equipment, and both need oxmysql, ox_lib, ox_inventory running first.

Currency isn't deducted on QBCore / Qbox

Create an awaken_coin ox_inventory item, or change the currency in config to money / bank / another item.

A combo plays no animation

The animation dictionary/clip must exist (a streamed .ycd or a base-game dict). A missing dict means the clip won't play even though the combo logic runs.
